Расширение **Chrome Manifest V3**, которое позволяет вручную выделить несколько секций веб-страницы с помощью линейки в стиле Photoshop и сохранить каждую секцию как отдельное PNG-изображение. Оно поддерживает разделение областей с помощью направляющих линейки, прямоугольников выделения мышью и автоматического выделения по CSS-классу, с экспортом в высоком разрешении, который автоматически архивируется в папки с именами по временной метке.

## Возможности

### Разделение областей (три метода можно комбинировать)

- **Линейка в пикселях**: линейки сверху (ось X) и слева (ось Y) страницы, с делениями и цифрами, адаптированные для экранов HiDPI
- **Создание направляющих перетаскиванием**: удерживайте левую кнопку мыши на линейке и перетаскивайте, чтобы создать вертикальные / горизонтальные направляющие
- **Управление направляющими**: положение можно изменять перетаскиванием; щёлкните по направляющей, чтобы показать кнопку удаления; поддерживается очистка всех направляющих разом
- **Прямоугольник выделения**: после активации режима выделения перетаскивайте прямо по странице, чтобы выбрать любую область; этот прямоугольник становится областью снимка
- **Автовыделение (Class)**: введите имя CSS-класса, и расширение автоматически создаст прямоугольники выделения для всех подходящих элементов

### Снимок и экспорт

- **Экспорт в высоком разрешении**: холст всей страницы и сохраняемые PNG рендерятся в `размер документа × devicePixelRatio × EXPORT_SCALE`, с увеличением в 2 раза для более чёткого результата
- **Обрезка секций в PNG**: одним щелчком каждая область (ячейка сетки направляющих + прямоугольник выделения) сохраняется как отдельное PNG-изображение
- **Модальное окно прогресса**: подробный индикатор выполнения, текущее/всего, операция отмены и обратная связь о завершении (с кнопкой «открыть папку загрузок»)
- **Загрузка больших изображений**: использует офскрин-документ для отправки data URL частями и преобразования в Blob, обходя ограничение в 2 МБ для data URL в `chrome.downloads`, поэтому сверхвысокое разрешение сохраняется полностью
- **Автоматическое архивирование по времени**: каждый набор сохраняется в отдельную папку с именем по текущему времени (например, `2026年08月25日 14时30分55秒_500_A1B2`), что предотвращает перезапись и засорение каталога

### Удобство использования

- **Правило именования PNG**: `номер_имя_сайта.png` (например, `1_example.png`), где имя сайта автоматически извлекается из URL
- **Сохранение направляющих**: направляющие автоматически восстанавливаются после обновления страницы и изолируются по URL, чтобы разные страницы не делили направляющие
- **Горячая клавиша**: по умолчанию нажмите `P` для быстрого переключения режима выделения (`ESC` для выхода), настраивается в настройках
- **Панель настроек**: позволяет настроить и сохранить горячую клавишу прямоугольника выделения
- **Управление с двух входов**: Popup на панели инструментов браузера + плавающая панель инструментов на странице

### Прочее

- **Угостить автора кофе**: встроенное всплывающее окно пожертвования с QR-кодом для поддержки автора

## Локальная загрузка (режим разработчика)

1. Откройте Chrome и перейдите на `chrome://extensions/`
2. Включите **режим разработчика** в правом верхнем углу
3. Нажмите **Загрузить распакованное расширение**
4. Выберите корневой каталог плагина (папку, содержащую `manifest.json`)

## Инструкция по использованию

1. **Установка направляющих**
   - Наведите мышь на **верхнюю линейку** страницы (ось X), удерживайте левую кнопку и перетащите вниз, чтобы создать **горизонтальную направляющую** (горизонтальную линию, представляющую координату Y).
   - Наведите мышь на **левую линейку** страницы (ось Y), удерживайте левую кнопку и перетащите вправо, чтобы создать **вертикальную направляющую** (вертикальную линию, представляющую координату X).
   - Во время перетаскивания текущая координата (в пикселях) отображается в реальном времени.
   - Направляющие позиционируются по **координатам документа** (закреплены за содержимым страницы) и перемещаются вместе со страницей при прокрутке.
2. **Настройка направляющих**
   - Удерживайте существующую направляющую и перетащите её, чтобы изменить положение.
   - Щёлкните по направляющей, чтобы показать красную кнопку удаления; щёлкните по ней, чтобы удалить эту направляющую.
3. **Использование прямоугольника выделения** (идеально для точного выделения области)
   - Нажмите кнопку «Включить прямоугольник выделения» на панели инструментов (или нажмите клавишу по умолчанию `P`).
   - После активации удерживайте левую кнопку и перетаскивайте прямо по странице; выбранный прямоугольник становится областью снимка. Можно выбрать несколько областей одновременно.
   - У каждого прямоугольника выделения есть кнопка удаления в правом верхнем углу; нажмите `P` ещё раз или `ESC`, чтобы выйти из режима выделения.
   - Горячую клавишу можно изменить и сохранить в настройках.
4. **Автовыделение (Class)**
   - Нажмите кнопку «Автовыделение (Class)» на панели инструментов.
   - Введите имя класса элементов страницы (начальную точку `.` можно опустить) и подтвердите.
   - Расширение автоматически создаст прямоугольники выделения для всех видимых элементов, соответствующих этому классу.
5. **Запуск обрезки**
   - Нажмите кнопку «Запустить обрезку PNG» на плавающей панели инструментов или в Popup.
   - Расширение скрывает линейки / направляющие / прямоугольники выделения / панель инструментов, снимает область за областью и показывает модальное окно прогресса.
   - Каждая область называется `номер_имя_сайта.png` и сохраняется в подпапку с именем по текущему времени.
   - После завершения нажмите «Открыть сохранённую папку», чтобы сразу увидеть результаты.
6. **Прочее**
   - «Очистить все направляющие» удаляет и все направляющие, и все прямоугольники выделения.
   - «Скрыть/Показать линейку» переключает отображение линейки.
   - «Настройки» изменяют горячую клавишу прямоугольника выделения.
   - «Угостить автора кофе» позволяет отсканировать QR-код для поддержки автора.

## Технические примечания

### Подход к снимку (склейка прокруткой + обрезка по области)

- **Основной подход**: **склейка прокруткой** — независимо от длины/ширины страницы (включая горизонтальные и вертикальные полосы прокрутки), сначала вся страница делится на сетку по размеру окна, затем прокручивается ячейка за ячейкой и вызывается `chrome.tabs.captureVisibleTab` для получения реального отрендеренного изображения.
  - В отличие от прежнего подхода «холст всей страницы», текущая реализация **больше не создаёт огромный холст всей страницы** (чтобы не превышать предел в 32 000 пикселей браузера и не получать пустые изображения). Вместо этого она **создаёт отдельный холст для каждой сохраняемой области** и во время прокрутки рисует пересечение окна и каждой области прямо в соответствующий холст, значительно снижая использование памяти и риск сбоя склейки.
  - Как видимые, так и невидимые (требующие прокрутки) части сохраняются полностью.
  - Направляющие / прямоугольники выделения — единственный критерий разделения; каждая область = ячейка сетки направляющих + выбранные пользователем прямоугольники.
  - Используются реальные отрендеренные снимки, с более высокой точностью, чем у html2canvas.
- **Ограничение частоты снимков**: `captureVisibleTab` регулируется (минимум 500 мс между двумя вызовами) и при ошибке квоты Chrome автоматически выполняет экспоненциальную паузу и повторную попытку, избегая прерывания во время покадрового снимка.
- **Увеличение HiDPI**: `EXPORT_SCALE` (по умолчанию 2) дополнительно увеличивает поверх dpr для более чёткого PNG.
- **Дополнительный подход**: `lib/html-to-image.js` (SVG `foreignObject`), доступен как запасной вариант для крайних случаев (например, внутренние контейнеры прокрутки), расширяется по мере необходимости.

### Загрузка больших изображений (офскрин-документ + сегментированная передача)

- **Проблема**: `chrome.downloads.download`, принимающий data URL напрямую, ограничен **2 МБ**, поэтому сверхвысокое разрешение может не сохраниться или ошибочно сохраниться как `.txt`; а `URL.createObjectURL` недоступен в Service Worker MV3.
- **Подход**: динамически создать **офскрин-документ**, который выполняет преобразование `data URL → Blob → blob URL` в обычной DOM-среде.
  - Content script разбивает большой data URL на части по 4 МБ и отправляет их по одной (`DOWNLOAD_CHUNK`); офскрин-документ накапливает их по имени файла;
  - После отправки всех частей ему сообщается, чтобы он собрал их по порядку в Blob и создал blob URL (`DOWNLOAD_ASSEMBLE`); отсутствующие части вызывают ошибку, а не повреждённый файл;
  - Финальное действие загрузки выполняет Service Worker, используя blob URL через `chrome.downloads.download` (у офскрин-документа нет этого разрешения).
- Каждое изображение сохраняется в подпапку с именем по временной метке, что предотвращает перезапись и засорение каталога.

### Архитектура кода (высокая связность, низкая связанность)

- Каждый модуль функций инкапсулируется независимо в `content/modules/` и монтируется в глобальное пространство имён `SSS` (загружается манифестом в порядке зависимостей, а не как ES-модули).
- Входная точка `index.js` отвечает только за **внедрение зависимостей и сборку**, без бизнес-логики.
- Модули общаются через **колбэки / сообщения**, избегая прямых зависимостей.
- Весь интерфейс находится внутри **Shadow DOM**, полностью изолирован от стилей хост-страницы.
- Сохранение направляющих изолировано по URL (`{ sss_guides : { [url] : [] } }`), с использованием сериализованной очереди для избежания гонок чтения-изменения-записи.

### Примечания

- Склейка всей страницы зависит от API захвата окна браузера и прокручивает всю страницу ячейка за ячейкой; чем больше страница, тем дольше (около 250 мс ожидания на ячейку для завершения перерисовки).
- Если страница содержит элементы `position: fixed` (например, фиксированную панель навигации), они появляются в каждом сегменте окна при склейке — это неотъемлемое ограничение снимка всей страницы.
- Координаты направляющих основаны на документе (прокрутке `window`); если тело страницы находится во внутреннем контейнере прокрутки, возможно, потребуется нацелиться на этот контейнер.
- Из-за ограничений безопасности браузера некоторые специальные страницы (например, `chrome://`, Chrome Web Store) не могут быть инъецированы.
- Если страница содержит ресурсы с других доменов (cross-origin), API снимка возвращает реально отрендеренное изображение, не подверженное загрязнению холста cross-origin.
