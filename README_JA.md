**Chrome Manifest V3** ベースの拡張機能です。Photoshop 風のルーラー（定規）バーでウェブページの複数の部分を手動で選択し、各部分を独立した PNG 画像として保存できます。ルーラーガイド、マウス選択ボックス、CSS Class による自動選択など、複数の分割方法に対応し、高解像度でエクスポートしてタイムスタンプ名のフォルダーに自動で保存します。

## 機能一覧

### 領域の分割（3 つの方法は併用可能）

- **ピクセルルーラーバー**：ページ上部（X 軸）と左端（Y 軸）のルーラー。目盛りと数字付きで、HiDPI 画面に対応
- **ガイドのドラッグ作成**：ルーラー上でマウス左ボタンを押しながらドラッグすると、縦 / 横のガイドを作成できます
- **ガイド管理**：位置をドラッグして変更可能。ガイドをクリックすると削除ボタンが表示され、全ガイドを一括クリアも可能
- **選択ボックス**：選択ボックスモードを有効にすると、ページ上でマウスドラッグして任意の領域を選択でき、その枠がスクリーンショット領域になります
- **Class 自動選択**：CSS Class 名を入力すると、一致するすべての要素に選択ボックスが自動で作成されます

### スクリーンショットとエクスポート

- **高解像度エクスポート**：全ページ canvas と保存される PNG は `ドキュメントサイズ × devicePixelRatio × EXPORT_SCALE` でレンダリングされ、2 倍拡大でより鮮明に出力されます
- **区間クロップ PNG**：ワンクリックで、各領域（ガイドグリッドセル + 選択ボックス）を独立した PNG 画像として保存します
- **進捗モーダル**：詳細なプログレスバー、現在数/総数、キャンセル操作、完了フィードバック（「保存フォルダーを開く」ボタン付き）
- **巨大画像のダウンロード**：Offscreen Document を使用して data URL をチャンク分割して転送し Blob に変換するため、`chrome.downloads` の data URL 2MB 長さ制限を回避し、超高解像度スクリーンショットも完全に保存できます
- **時刻による自動保存**：各バッチは現在時刻で命名された独立フォルダー（例：`2026年08月25日 14時30分55秒_500_A1B2`）に保存され、上書きやディレクトリ汚染を防ぎます

### 使いやすさ

- **PNG 命名規則**：`番号_ウェブサイト名.png`（例：`1_example.png`）。ウェブサイト名は URL から自動解析
- **ガイドの永続化**：ページを更新するとガイドが自動復元され、URL ごとに分離されるためページ間で混在しません
- **ショートカットキー**：デフォルトで `P` キーで選択ボックスモードをすばやく切り替え（`ESC` で終了）。設定で変更可能
- **設定パネル**：選択ボックスのショートカットキーを設定・永続化できます
- **二重エントリ制御**：ブラウザツールバーの Popup + ページ内のフローティングツールバー

### その他

- **作者にコーヒーを**：QR コードで作者を支援できる寄付ポップアップを内蔵

## ローカル読み込み方法（開発モード）

1. Chrome を開き、`chrome://extensions/` にアクセスします
2. 右上の**デベロッパーモード**をオンにします
3. **パッケージ化されていない拡張機能を読み込む**をクリックします
4. 本プラグインのルートディレクトリ（`manifest.json` を含むフォルダー）を選択します

## 使い方

1. **ガイドを設定する**
   - ページ**上部のルーラー**（X 軸）にマウスを移動し、左ボタンを押しながら下にドラッグすると、**横向きガイド**（Y 座標を表す水平線）が作成されます。
   - ページ**左側のルーラー**（Y 軸）にマウスを移動し、左ボタンを押しながら右にドラッグすると、**縦向きガイド**（X 座標を表す垂直線）が作成されます。
   - ドラッグ中は現在の座標（ピクセル）がリアルタイムに表示されます。
   - ガイドは**ドキュメント座標**で配置され（ページコンテンツに固定）、スクロールするとページに合わせて移動します。
2. **ガイドを調整する**
   - 作成済みガイドを押したままドラッグすると位置を変更できます。
   - ガイドをクリックすると赤い削除ボタンが表示され、クリックでそのガイドを削除できます。
3. **選択ボックスを使う**（領域を正確に選択するのに最適）
   - ツールバーの「選択ボックスを有効にする」ボタン（またはデフォルトショートカット `P`）をクリックします。
   - 有効後、ページ上で左ボタンを押しながらドラッグすると、選択した矩形がスクリーンショット領域になります。複数の領域を同時に選択できます。
   - 各選択ボックスの右上に削除ボタンがあります。`P` をもう一度押すか `ESC` で選択モードを終了します。
   - ショートカットは設定で変更・保存できます。
4. **Class 自動選択**
   - ツールバーの「Class 自動選択」ボタンをクリックします。
   - ページ要素の Class 名を入力し（先頭の `.` は省略可）、確認します。
   - その Class に一致するすべての可視要素に選択ボックスが自動で作成されます。
5. **クロップを開始する**
   - フローティングツールバーまたは Popup の「PNG クロップ開始」ボタンをクリックします。
   - ルーラー / ガイド / 選択ボックス / ツールバーが隠れ、領域ごとにスクリーンショットが撮影され、進捗モーダルが表示されます。
   - 各領域は `番号_ウェブサイト名.png` として、現在時刻で命名されたサブフォルダーに保存されます。
   - 完了後、「保存フォルダーを開く」をクリックすると結果を直接確認できます。
6. **その他**
   - 「全ガイドをクリア」で、すべてのガイドと選択ボックスをまとめて削除できます。
   - 「ルーラーを隠す/表示」でルーラーバーを切り替えます。
   - 「設定」で選択ボックスのショートカットキーを変更できます。
   - 「作者にコーヒーを」で QR コードをスキャンして作者を支援できます。

## 技術メモ

### スクリーンショット方式（スクロール結合 + 領域ごとのクロップ）

- **主方式**：**スクロール結合**——ページがどれほど長く/広くても（横・縦のスクロールバーを含む）、まずページ全体をビューポートサイズでグリッドに分割し、セルごとにスクロールしながら `chrome.tabs.captureVisibleTab` を呼び出して実際のレンダリング画像を取得します。
  - 以前の「全ページ canvas」方式とは異なり、現在の実装では**巨大な全ページ canvas は作成せず**（ブラウザの 32k ピクセル制限を超えて空白になるのを避ける）、**保存する各領域ごとに独立した canvas を作成**し、スクロール中にビューポートと各領域の交差部分を対応する領域 canvas に直接描画します。メモリ使用量と結合失敗のリスクを大幅に削減します。
  - 可視部分と不可視部分（スクロールが必要）の両方が完全に保存されます。
  - ガイド / 選択ボックスが唯一の分割基準であり、各領域 = ガイドグリッドのセル + ユーザー選択ボックスです。
  - html2canvas よりも忠実度の高い、実際のレンダリング画像を使用します。
- **キャプチャ頻度制御**：`captureVisibleTab` をスロットリングし（2 回の呼び出し間隔を最低 500ms）、Chrome のクォータエラー発生時には自動でバックオフして再試行します。セル単位のキャプチャ中に中断されるのを防ぎます。
- **高解像度拡大**：`EXPORT_SCALE`（デフォルト 2）で dpr にさらに拡大し、より鮮明な PNG を出力します。
- **補足方式**：`lib/html-to-image.js`（SVG `foreignObject`）。内部スクロールコンテナなどの極端なケース向けの代替として、必要に応じて拡張できます。

### 巨大画像のダウンロード（オフスクリーンドキュメント + チャンク転送）

- **問題点**：`chrome.downloads.download` が data URL を直接受け取る場合、**2MB** の長さ制限があるため、超高解像度スクリーンショットは失敗するか `.txt` として誤保存されます。また、MV3 の Service Worker では `URL.createObjectURL` が使用できません。
- **方式**：通常の DOM 環境で `data URL → Blob → blob URL` 変換を行う**オフスクリーンドキュメント**を動的に作成します。
  - Content Script が巨大な data URL を 4MB 単位のチャンクに分割して順番に送信し（`DOWNLOAD_CHUNK`）、オフスクリーンドキュメントがファイル名ごとに蓄積します。
  - 全チャンク送信後に組み立てを通知され、順番に連結して Blob にし、blob URL を生成します（`DOWNLOAD_ASSEMBLE`）。チャンクが欠けている場合は、壊れたファイルを作る代わりにエラーになります。
  - 最終的なダウンロードは Service Worker が blob URL を使って `chrome.downloads.download` で実行します（オフスクリーンドキュメントにはその権限がありません）。
- 各画像はタイムスタンプ名のサブフォルダーに保存され、上書きやディレクトリ汚染を防ぎます。

### コードアーキテクチャ（高凝集・低結合）

- 各機能モジュールは `content/modules/` 下に独立してカプセル化され、グローバルな `SSS` 名前空間にマウントされます（ES Module ではなく、manifest が依存順に読み込みます）。
- エントリ `index.js` は**依存注入と組み立て**のみを担当し、ビジネス実装は含みません。
- モジュール間は**コールバック / メッセージ**で通信し、直接依存を避けます。
- UI はすべて **Shadow DOM** 内にあり、ホストページのスタイルから完全に分離されています。
- ガイドの永続化は URL ごとに分離して保存され（`{ sss_guides: { [url]: [] } }`）、読み取り・変更・書き込みの競合を避けるためシリアルキューを使用します。

### 注意事項

- 全ページ結合はブラウザのビューポートキャプチャ API に依存し、ページ全体をセルごとにスクロールします。ページが大きいほど時間がかかります（セルごとに再描画完了まで約 250ms 待機）。
- ページに `position: fixed` の要素（固定ナビバーなど）がある場合、結合中にその要素がすべてのビューポートセグメントに現れます。これは全ページキャプチャの固有の制限です。
- ガイド座標はドキュメント（`window` スクロール）に基づいています。ページ本文が内部スクロールコンテナ内にある場合は、対象コンテナを調整する必要があるかもしれません。
- ブラウザのセキュリティ制限により、一部の特殊ページ（`chrome://` やストアなど）にはスクリプトを注入できません。
- ページがクロスオリジンリソースを含む場合、キャプチャ API は実際のレンダリング画像を返すため、canvas のクロスオリジン汚染の影響を受けません。

## テストチェックリスト

- [x] すべての JS ファイルが構文チェックを通過（`node --check`）
- [x] `manifest.json` が JSON 検証を通過し、参照ファイルがすべて存在
- [x] 命名規則の単体検証（URL → ウェブサイト名 → ファイル名）
- [x] 区間アルゴリズムの単体検証（領域数、総面積カバー、重複なし）
- [ ] 多様な典型的なページ（長いページ、スクロールページ、fixed 要素を含むページ）で実測
- [ ] ガイドのドラッグ、変更、削除、一括クリアを実測
- [ ] 選択ボックスのドラッグ、ショートカット切り替え、Class 自動選択を実測
